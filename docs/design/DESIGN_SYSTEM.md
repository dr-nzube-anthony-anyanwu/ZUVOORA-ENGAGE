# ZUVOORA Engage — Design System

Version 2 (2026-11-22, official logo and colours). Applies to the public website, the sign-in pages and, progressively, the
staff dashboard and the chat widget. Brief: `prompts/DESIGN_UI_UX_BRIEF.md`.

## Brand and logo
- **Official logo** supplied by the founder (2026-11-22). The original artwork is kept unchanged
  in `docs/brand/zuvoora-engage-logo-original.png`. Derived files (cropped from it, no redrawing):

  | File | Content | Used for |

  | `apps/web/public/brand/zuvoora-engage-logo.png` (540×131) | Eye symbol + divider + "ZUVOORA Engage" | Header, footer, sign-in, dashboard sidebars |
  | `apps/web/public/brand/zuvoora-engage-logo-full.png` | Full artwork incl. tagline | Reference / large print use |
  | `apps/web/public/brand/zuvoora-engage-mark.png` (223×223) | Eye symbol only | Square uses |
  | `apps/web/app/icon.png` (64×64), `app/apple-icon.png` (180×180) | Eye symbol | Browser tab and home-screen icons |

- Component: `components/marketing/Wordmark.tsx` (`size` sm 168 px / md 212 px / lg 264 px wide;
  mobile md 176 px). The tagline "Patient Communication & Engagement Platform for Eye Care" is
  rendered as real text (`withTagline`) because inside the artwork it would be unreadably small.
- **Light backgrounds only.** The wordmark's navy lettering disappears on dark colours, so the
  logo never sits on navy (the footer and the sign-in panel use light backgrounds). A reversed
  (white) version would need to be supplied as artwork; it is not generated by recolouring.
- Minimum display width 160 px; keep clear space of at least the height of the "Z" around it.
- Request a vector (SVG) version from the designer for print and very large displays.

## Typography
- **Plus Jakarta Sans** (600/700/800) for headings, **Inter** for interface and body — both
  self-hosted by `next/font` at build time (CSP `font-src 'self'`; no requests to Google).
- CSS variables: `--font-heading`, `--font-body`. Fallback: system UI fonts.
- Scale (fluid with `clamp`): hero 38–64 px; section titles 30–46 px; feature titles 22–28 px;
  card titles 19 px; body 17 px (16 px on mobile); small 13–15 px. Headings use slight negative
  letter-spacing and `text-wrap: balance` on the hero.

## Space, shape and depth
- Container 1200 px with 24 px gutters (16 px on mobile). Sections 64–112 px vertical padding.
- Radii: `--radius-sm` 8, `--radius` 12, `--radius-lg` 20, `--radius-xl` 28; pills 999 px.
- Shadows: `--shadow-sm`, `--shadow`, `--shadow-lg` (navy-tinted, low opacity).
- Breakpoints: 1020 px (navigation collapses, two-column layouts stack), 760 px (single column).

## Accessibility rules
- WCAG 2.2 AA target; automated axe checks (wcag2a/aa, 2.1 a/aa, 2.2 aa) in
  `apps/web/e2e/marketing.spec.ts` for the homepage, demo request, accessibility statement and
  sign-in pages (the homepage also at 375 px width).
- One `h1` per page; sections are `<section aria-labelledby>`; skip link to `#main`.
- Visible focus everywhere (`:focus-visible` 3 px royal-blue outline).
- Native `<details>` for the FAQ accordion and mobile menu (keyboard and screen-reader support
  without scripts). No carousels and no autoplay.
- `prefers-reduced-motion: reduce` disables animations and transitions.
- Touch targets ≥ 44 px for buttons and chips; form fields 48 px high.
- No horizontal page scrolling at 375 px; the plan table scrolls inside a labelled, focusable
  region.

## Content rules
- Only claim what is live (capability table in the brief, §3). Planned features carry a
  "Coming soon" badge. No statistics, testimonials, logos, certifications or guarantees.
- Illustrations use the fictional "Lumen Eye Clinic (sample)" and are labelled.
- Never ask for health or patient information on public forms.

## Staff dashboard (D4)
- Shared classes in `app/globals.css` (`.shell`, `.sidebar`, `.panel`, `.table`, `.badge`, `.tabs`,
  `.field`, buttons) use the same tokens; page markup, labels and roles are unchanged.
- `components/NavLink.tsx` marks the current section with `aria-current="page"` (highlighted and
  announced). The sidebar stays in view on desktop; on phones the sections become one
  horizontally scrolling row so the page content starts near the top.
- The clinic overview shows the onboarding line "Let's teach Engage about your clinic." and a
  progress bar while setup is incomplete.
- Automated axe checks for the dashboard (`apps/web/e2e/dashboard-a11y.spec.ts`).

## Chat widget (D4)
- `apps/widget/src/frame.css` mirrors the tokens (navy header with a green status dot, royal-blue
  actions, rounded bubbles, visible focus). System fonts only: the widget runs on clinics'
  websites and makes no requests beyond the API.
- "Book an appointment" and "Contact the clinic team" are pill buttons; the call-back and booking
  panels scroll within a capped height so the conversation stays visible.
- The launcher button (`loader.ts`) uses the navy and a 48 px touch target.
- The widget is branded with the clinic's name, not ZUVOORA, because it represents the clinic.
